# 类目与指标统计口径

## 1. 一级类目选择规则

优先采用站点原生的一级 merchandising 结构：
- 顶部一级导航
- 一级 collection / category
- 一级商品大类

如果站点结构不规整：
- 统一映射到一个可比较层级
- 保持“同一层级”比较，不混入二级/三级类目

默认不把以下营销型集合当作核心一级类目：
- New Arrivals
- Best Sellers
- Sale
- Gifts
- 节日/活动 campaign 集合

除非用户明确要求统计这些集合，否则仅将它们当作辅助观察信息，不纳入 Top 5 一级类目。

## 2. SPU 定义

一个 SPU = 一个去重后的商品详情页实体。

推荐去重键：
- canonical product URL
- product handle
- PDP 唯一 ID

规则：
- 同一个 PDP 下的尺寸/颜色/色号等变体，不拆成多个 SPU
- 同一商品如果同时出现在多个 collection 中，在单个类目统计内只计 1 次
- 如果同一商品跨多个一级类目同时出现，先判断该站点是否本身存在真实交叉归属；如无法确认，保留站点原生归属，不人为重复扩增

## 3. 价格口径

优先使用当前销售价。

如果同时存在：
- 原价（compare at / list price）
- 折后价（sale / current price）

则默认使用：
- 当前真实销售价

如果一个产品有多个变体价格：
- 默认取该产品当前可售变体中的**最低销售价**作为产品价格
- 在同一品牌内保持口径一致

如果页面只展示价格区间：
- 默认取区间下限作为产品价格
- 如站点能通过 JSON/API 拿到更准确的当前变体价格，优先使用结构化数据

## 4. 指标定义

对每个一级类目计算：

### SPU 数
- 去重后商品数

### 平均价格
- 该类目所有有效产品价格的算术平均值

### 中位数
- 该类目所有有效产品价格排序后的中位数

无效价格应排除：
- 缺失
- 无法解析
- 显然不是商品售价的字段

## 5. Top 5 选择规则

按以下顺序排序：
1. SPU 数降序
2. 如果 SPU 数相同，优先站点导航层级更靠前的类目
3. 如果仍相同，优先品牌表达更明确、边界更清晰的类目

最终输出 Top 5。

如果有效一级类目不足 5 个：
- 保留已有类目
- 剩余槽位留空，不强行补伪类目

## 6. Top 3 商品选择口径（用于 concat 图与 Wiki 明细页）

当用户要求示例图片，或要求同步写 Wiki 品牌明细页时：
- Top 3 商品必须来自用于统计该一级类目的**同一有序商品集合**
- 默认按该类目主 collection/category 页的默认 merchandising 顺序取前 3 个
- 如果页面存在显式 sort 参数或个性化排序，优先使用无个性化的默认排序链接
- 同一类目内先按 product handle / PDP 去重，再按 image URL 去重，避免同商品或同图片重复进入 top 3
- 如果商品缺失有效 hero 图，则跳过并顺延下一商品
- 如果有效商品不足 3 个，则保留现有 1-2 个，不强行补足 3 个
- 一旦 top 3 集合确定，这个集合就是 concat 图片和 Wiki 明细行的唯一来源；后续步骤不得重新选另一批商品

## 7. 摘要文案格式

“品牌定位 + 类目结构摘要”里如果提到均价：
- 必须写成整数
- 使用四舍五入后的值

示例：
- `Eyes 均价约 $18`
- `Face 均价约 $24`

不要写：
- `$17.85`
- `$24.09`

注意：
- 这个整数化规则只适用于摘要文案
- 飞书数值单元格中的均价/中位数，是否保留小数，以用户当前表格写入需求为准

## 8. 适用范围提醒

这个 skill 面向“网站类目结构探索 + Top 5 一级类目指标 + 飞书写回”的场景。

如果用户要的是：
- Best Seller TOP 200 逐商品抓取
- 自然类目/标准类目双层明细表
- 更大规模的商品明细采集

可以在当前 workflow 基础上扩展，但默认仍以本 skill 中定义的类目统计、top 3 商品锁定、concat 图片生成与飞书写回流程为准。
